This Privacy Policy explains which personal data is processed when you use WG-Link, for what purpose, and which rights you have.

1. Controller

The controller for data processing in connection with the bot WG-Link is:

  • Discord username: motti_tv
  • Application: WG-Link

Contact for privacy requests: Discord message to motti_tv (or the admin channel named on that server, if the bot is only operated there).

2. What is WG-Link?

WG-Link is a Discord bot that can be used on one or more Discord servers. It links Discord users with their Wargaming / World of Warships account. After a successful link on a particular server, the bot can set, among other things:

  • the server nickname (style is selectable, for example [CLAN] Player name (EU) or only Player name (EU)),
  • a verified role on that Discord server.

The link applies per Discord server. Anyone who uses the bot on another server must link there again. One Wargaming account may still be assigned to only one Discord account.

Login uses the official Wargaming OpenID login. The bot does not receive or store passwords.

After linking, the bot can fetch public WoWS profile data (player name and clan) again later, so the nickname and clan tag stay current on that server (/link refresh, or admin/mod /link-check resync).

3.2 Update after linking (refresh / resync)

A new Wargaming login is not required for this. The bot only reads public data from the WoWS API (player name, clan membership / clan tag) and, when needed, updates the stored link and the Discord server nick.

A resync collects no new kinds of data. It reads again the same public profile data already used when linking. The action is manual (from time to time, by staff), not continuous in the background.

Members without a stored link on this server, or without the WG-Link role, are not updated during resync. Accounts that are no longer on the server are skipped.

3.4 Temporary data (login)

During login a short-lived state token is stored (typically about 15 minutes at most). It ties the Discord user, server, region, and locale to the callback. After that the token is gone, or it is used up and deleted.

3.5 Technically necessary data

When the bot’s login or callback page is opened, ordinary server logs can be created (for example time, IP address, user agent — depending on hosting, ngrok, or a proxy). These are used for security and troubleshooting, not for marketing.

Bot logs can also contain technical notes (for example that a refresh/resync ran). They are for operation, not for marketing.

3.6 What is not stored

  • No Wargaming or Discord passwords
  • No payment details
  • No private message contents for the purpose of linking (except the interactions needed for commands)
  • No lasting Wargaming access token in the link database (a login token is used only for the callback and is not stored permanently)
  • No campaign, ship, or battle statistics beyond the public profile (name + clan)
  • No profiling for advertising

4. Legal bases and purposes (GDPR orientation)

Where the GDPR applies, processing is based in particular on:

  • Art. 6 (1) (b) GDPR — performing the link you requested (including keeping nick/clan current as part of that function),
  • Art. 6 (1) (f) GDPR — legitimate interest in secure operation, preventing abuse, and server administration (admins/mods: check status, compare nick/clan),
  • Art. 6 (1) (a) GDPR — consent, where you actively start and finish the linking process.

Purposes in short:

  1. Carry out the account link
  2. Set and keep current the nickname (including clan tag) and the verified role
  3. Show link status (/link status and similar)
  4. User refresh (/link refresh) and unlink (/link unlink)
  5. Admin/mod functions: set up the server, check, list, scan, set nick style, resync nick/clan, remove a link, compare roles
  6. Operation on more than one Discord server (settings and links kept separate)
  7. Security and detecting abuse (for example the same WG account assigned to another Discord account)

5. Storage and location

  • Link data and server settings are stored in storage on the bot’s side (currently on the bot’s hosting, for example a Railway volume).
  • Retention: for as long as the link on that server is active, or until deletion (by /link unlink on that server, an admin command, manual deletion, or the end of the service). Deleting the link on server A does not automatically remove the link on server B.
  • Temporary login states: usually a few minutes, then unusable or removed.

Personal data is not sold to third parties.

Absolute security on the internet cannot be guaranteed.

11. Automated decisions

There is no automated decision-making in the sense of profiling with legal effect.

As part of linking, the bot sets a role and a nickname. A later refresh/resync changes only the stored record and the server nick when the public WoWS name or clan has changed. There is no scoring, rating, or advertising analysis.

3.4 Dane tymczasowe (logowanie)

Podczas logowania zapisywany jest krótkotrwały token state (zwykle maksymalnie około 15 minut), który przypisuje użytkownika Discord, serwer, region i język do callbacku. Potem token odpada albo zostaje zużyty i usunięty.

3.5 Dane technicznie konieczne

Przy otwarciu strony logowania albo callbacku bota mogą powstać zwykłe logi serwera (na przykład czas, adres IP, user agent — zależnie od hostingu, ngrok albo proxy). Służą bezpieczeństwu i analizie błędów, nie marketingowi.

Logi bota mogą dodatkowo zawierać wskazówki techniczne (na przykład że wykonano refresh/resync). Służą działaniu, nie marketingowi.

3.6 Czego nie zapisujemy

  • Żadnych haseł Wargaming ani Discord
  • Żadnych danych płatniczych
  • Żadnej treści prywatnych wiadomości w celu łączenia (poza interakcjami potrzebnymi do komend)
  • Żadnego trwałego tokenu dostępu Wargaming w bazie połączeń (token logowania służy tylko callbackowi i nie jest przechowywany na stałe)
  • Żadnych statystyk kampanii, okrętów ani bitew poza publicznym profilem (nazwa + klan)
  • Żadnego profilowania do celów reklamowych

4. Podstawy prawne i cele (orientacja RODO)

Gdy stosuje się RODO, przetwarzanie odbywa się w szczególności na podstawie:

  • art. 6 ust. 1 lit. b RODO — wykonanie żądanego przez ciebie połączenia (w tym utrzymywanie aktualnego nicku/klanu jako części tej funkcji),
  • art. 6 ust. 1 lit. f RODO — prawnie uzasadniony interes bezpiecznego działania, zapobiegania nadużyciom i administracji serwera (admini/moderatorzy: sprawdzanie statusu, porównanie nicku/klanu),
  • art. 6 ust. 1 lit. a RODO — zgoda, o ile sam zaczynasz i kończysz proces łączenia.

Cele w skrócie:

  1. Wykonanie połączenia kont
  2. Ustawienie i utrzymanie aktualnego nicku (w tym tagu klanu) oraz roli weryfikacji
  3. Pokazanie statusu połączenia (/link status i podobne)
  4. Aktualizacja przez użytkownika (/link refresh) i rozłączenie (/link unlink)
  5. Funkcje admina/moderatora: konfiguracja serwera, sprawdzanie, listy, skan, styl nicku, resync nicku/klanu, usunięcie połączenia, porównanie ról
  6. Działanie na wielu serwerach Discord (ustawienia i połączenia osobno)
  7. Bezpieczeństwo i wykrywanie nadużyć (na przykład podwójne przypisanie tego samego konta WG do innego konta Discord)

5. Przechowywanie i miejsce

  • Dane połączeń i ustawienia serwera są przechowywane w magazynie po stronie bota (obecnie na hostingu bota, na przykład volume Railway).
  • Czas przechowywania: dopóki połączenie na danym serwerze jest aktywne, albo do usunięcia (przez /link unlink na tym serwerze, komendę admina, ręczne usunięcie albo zakończenie usługi). Usunięcie na serwerze A nie usuwa automatycznie połączenia na serwerze B.
  • Tymczasowe stany logowania: zwykle kilka minut, potem bezużyteczne albo usunięte.

Dane osobowe nie są sprzedawane osobom trzecim.

8. Twoje prawa

Gdy stosuje się właściwe prawo ochrony danych (na przykład RODO), masz w szczególności prawo do:

  • dostępu do danych zapisanych o tobie,
  • sprostowania nieprawidłowych danych,
  • usunięcia („prawo do bycia zapomnianym”),
  • ograniczenia przetwarzania,
  • sprzeciwu wobec przetwarzania na podstawie prawnie uzasadnionego interesu,
  • przenoszenia danych, o ile jest to technicznie i prawnie możliwe,
  • skargi do organu nadzorczego ochrony danych.

Usunięcie połączenia

  1. Sam na tym serwerze: /link unlink (potwierdzić),
  2. Admin tego serwera: /link-check remove,
  3. Prośba do prowadzącego (motti_tv na Discordzie),
  4. Usunięcie bota z serwera (kończy korzystanie na tym serwerze; zapisane dane połączenia mogą wymagać osobnego usunięcia).

Po usunięciu połączenia dane połączenia po stronie bota odpadają; role i nicki po stronie Discord mogą wymagać ręcznej poprawki.

9. Małoletni

Bot jest dla użytkowników, którzy mogą korzystać z Discorda i właściwych usług gry. Osoby poniżej obowiązującego wieku minimalnego nie powinny korzystać z bota. Dane dzieci nie są świadomie zbierane do celowego profilowania.

10. Bezpieczeństwo

Prowadzący stosuje odpowiednie środki techniczne i organizacyjne, w tym:

  • brak zapisywania haseł,
  • użycie oficjalnego przepływu logowania Wargaming,
  • krótkotrwałe parametry state dla callbacku,
  • dostęp do zapisanych połączeń tylko dla działania oraz uprawnionych adminów/moderatorów (przez komendy bota),
  • resync tylko ręcznie i z cooldownem, żeby publiczne API nie były obciążane bez potrzeby.

Bezwzględnego bezpieczeństwa w internecie nie da się zagwarantować.

11. Zautomatyzowane decyzje

Nie ma zautomatyzowanego podejmowania decyzji w rozumieniu profilowania ze skutkiem prawnym.

W ramach łączenia bot ustawia rolę i nick. Późniejszy refresh/resync zmienia tylko zapisany stan i nick na serwerze, gdy zmieniła się publiczna nazwa WoWS albo klan. Nie ma oceny, scoringu ani analizy reklamowej.
